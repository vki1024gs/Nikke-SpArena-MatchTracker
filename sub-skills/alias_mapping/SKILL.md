# alias-mapping

## Purpose
将用户输入的角色昵称串解析为5人全名。

## 文件结构
- `SKILL.md` — 流程定义
- `alias_mapping.py` — 解析脚本（通过根目录 `scripts/common.py` 读取 `config.toml` 中的 alias 映射路径）
- `alias_mapping_pvp.toml` — 别名数据

## Workflow
1. 运行 `python3 <此目录>/alias_mapping.py '<昵称串>'`
2. 脚本自动清洗输入，执行贪婪最长匹配，内置完整性验证（5人、无重复、均为有效角色）
3. 检查 stderr：有 `[FAIL]` 则按「错误类型与处理」修正，无 FAIL 则 stdout 输出5个全名

## 运行模式

| 模式 | 用法 | 输出 |
|------|------|------|
| 默认 | `python3 alias_mapping.py '昵称串'` | stdout 每行一个全名，stderr 仅简要警告（`[WARN]`） |
| JSON | `--json` | stdout 输出 `{"input", "names", "count", "complete"}` |
| 调试 | `--debug` | stderr 输出每个昵称的匹配过程 + 验证详情（`[FAIL]`） |

## 匹配策略
- 从左到右贪婪最长匹配
- 输入和别名均转为小写比较，大小写不敏感（如 `emt` → 爱蜜莉雅）
- 全名也可作为子串匹配（优先级低于最长别名）

**贪婪示例**：
- `豺重白兔lpls` → `豺` + `重白` + `兔` + `lpls`
  - "重白" 比 "重" 更长，优先匹配 `白雪公主：重型武装`
  - 不会匹配为 `豺` + `重` + `白兔`

## 冲突处理
- `诺诺` 连续出现 → 第一个取诺伊斯，第二个取诺雅（硬编码）
- 其他同名别名按 toml 定义顺序循环取

## 别名维护
stderr 出现 `[WARN] 无法识别` 时，向用户确认缺失昵称，确认后提供角色与别名的追加示例供用户查看再次确认，才可追加到 `alias_mapping_pvp.toml`。

## 错误类型与处理

| stderr 信号 | 含义 | 处理方式 |
|-------------|------|----------|
| `[WARN] 无法识别: 'xxx', 停止解析` | 输入的某个昵称不在别名表中 | 向用户确认该昵称对应哪个角色，确认后追加到 `alias_mapping_pvp.toml` |
| `[WARN] 解析出 N 人，需要补全至5人` | 解析结果不足5人（N≠5） | 检查输入是否漏了角色，LLM 手动补全 |
| `[WARN] 解析出 6+ 人，需要补全至5人` | 别名冲突导致拆分过多 | 检查是否有单字别名拆了全名（如"伊"拆了"贝伊"），需补全冲突角色的映射 |
| `[WARN] 重复角色: xxx（位置 N 和 M）` | 同一角色出现两次 | 检查用户是否手误，或别名映射有误；同一队伍不可有相同角色 |

**排错提示**：遇到不确定的错误时，追加 `--debug` 参数运行，查看完整的匹配过程和验证详情。
